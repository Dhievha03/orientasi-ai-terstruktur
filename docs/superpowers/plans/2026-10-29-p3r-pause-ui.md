# P3R Pause UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use native execution in the current session after approval.

**Goal:** Replace the current presentation-like menu with a pause composition grounded in the supplied P3R video, and align slides/dialogs with its submenu language.

**Architecture:** Keep the content, presentation state, calendar, and navigation in place. Move pause composition into a dedicated renderer and stylesheet. Apply the shared submenu language through a focused presentation stylesheet and small renderer changes.

**Tech Stack:** Static HTML, CSS, vanilla JavaScript, inline SVG, existing WebGL/Canvas water, local fonts, Playwright with Microsoft Edge for verification.

**Spec:** `../specs/2026-10-29-p3r-pause-design.md`

## Global Constraints

- No characters, people, game assets, audio, backend, external runtime requests, or generated background images.
- Preserve 28 slides, 10 chapters, Indonesian AI-workflow content, and manual progression.
- No code material, menu numbering, phase names, focus outlines, or extra underlines.
- Preserve approved calendar composition and timings.
- Preserve storage, keyboard interaction, dialog closing, reduced-motion, and offline operation.
- No commits or Git configuration changes are requested.

## Review Focus

- Long labels and font loading must not misalign hit areas or selection artwork.
- Moving selection must not turn unreadable when the triangle crosses text.
- Menu/dialog closure during reduced-motion changes must not lock navigation.
- New slide panels must retain reading space on 1366×768 and mobile screens.
- Existing state must restore correctly after a reload and remain usable without storage/WebGL.
